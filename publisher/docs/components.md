## `Config` (`config.hxx` / `config.cxx`)

Top-level configuration aggregate. Also handles embedded web file installation.

`Validate(forceInstall)`:
- Canonicalizes all configured paths.
- Installs embedded web files into `htmlPath/publisher/`:
  - **Application files** (overwritten with `--force-install`): `summary_PR.html`, `.css`, `.js`, and all graph/metrics modules + `plotly-3.3.0.min.js`.
  - **Config file** (written only if absent, **never overwritten**): `summary_PR_config.js`.

---

## `ns_Server::MyServerApp` (`server/server.hxx` / `server/server.cxx`)

Extends `Poco::Util::ServerApplication`. Creates a `ServerSocket` (plain or SSL depending on config) and starts the `HTTPServer`. Blocks until `SIGTERM` or `SIGINT`.

---

## `RequestHandlerFactory` (`server/request_handler_factory.hxx`)

Routes by URI regex to typed handler classes generated by the `REQUESTHANDLER` macro. Captured URI groups become constructor arguments.

---

## `RequestHandler` subclasses (`server/request_handler.hxx` / `.cxx`)

| Handler | Route | Behavior |
|---------|-------|----------|
| `RequestHandlerNotify` | `POST /api/notify` | Parses multipart form (via `PartsHandler`), validates paths, calls `PublishAPI::NotifyFiles()` |
| `RequestHandlerProjectData` | `GET /api/project/{name}/data` | Returns JSON list of `.project/` files for the named project |
| `RequestHandlerFiles` | `GET /files/{path}` | Serves from `storagePath`; if path is a project root with a `.rules` `index` field, serves from `htmlPath/publisher/` instead |
| `RequestHandlerHTML` | `GET /html/{path}` | Serves from `htmlPath`, path traversal blocked |
| `RequestHandlerOptions` | `OPTIONS *` | CORS preflight response |

All handlers call `ManageCORS()` to add `Access-Control-Allow-Origin: *` headers.

---

## `ns_Server::PartsHandler` (`server/parts_handler.hxx` / `.cxx`)

Extends `Poco::Net::PartHandler` for multipart/form-data parsing. Reads each part's `Content-Disposition` header (`name`, `filename`, `Content-Type`) and streams the body into a `std::vector<uint8_t>`. Results stored in an `unordered_multimap<string, PartData>`.

Used exclusively by `RequestHandlerNotify` to parse the `src` and `dst` fields from `POST /api/notify`.

---

## `PublishAPI` (`api/publish_api.hxx` / `.cxx`)

Facade exposed to request handlers. Key methods:
- `NotifyFiles(dst, srcs)` — validates paths, delegates to `Publish::NotifyFiles()`.
- `Storage()` — returns the `storagePath` for use in file handlers.
- `HTMLStorage()` — returns the `htmlPath`.

---

## `APIS` (`api/api.hxx`)

Aggregate struct holding `PublishAPI publishAPI_`. Passed by reference to the entire server layer.

---

## `Publish` (`publish/publish.hxx` / `.cxx`)

Background processing thread. Holds the project list and the processing queue.

- `NotifyFiles(SNotifyFiles)` — pushes a notification to the queue and signals the worker.
- Thread loop: wakes on notification or `orphanScanInterval`; calls `Project::ScanFiles()` for notified files or `Project::ScanStorage()` for the periodic scan.

Concurrency:
- Queue protected by `std::mutex` + `std::condition_variable`.
- Project list protected by `std::shared_mutex` (shared reads, exclusive writes on project addition).

---

## `Project` (`publish/project.hxx` / `.cxx`)

Represents one data directory under `storagePath`. Holds:
- A list of `Rule` objects loaded from `.rules` files (recursive scan).
- A persistent `Index`.

Key methods:
- `ScanFiles(files)` — processes a specific list of notified files (bypasses `filesInError_` and the index — always reprocesses).
- `ScanStorage()` — periodic full scan; skips files already indexed with a valid output JSON or in `filesInError_`.

`.rules` files are scanned recursively from the project directory. Each `.rules` file may contain a top-level `index` field (HTML file path) and named rule entries.

---

## `Rule` (`publish/rule.hxx` / `.cxx`)

Base class. Associates a regex pattern (`onFiles`) with a processing action.

Key methods:
- `Match(file)` — tests whether the rule applies to an archive path.
- `Apply()` — processes the archive, generates JSON, updates the index.

Shared utilities:
- `ExtractExperimentsFromFile/Buffer()` — parses task JSON metadata from archives.
- `MergeResults()` — merges multiple result documents into one.
- `UpdateTempJSON()` / `ValidateTempJSON()` — atomic write via `.tmp` + `rename()`.

Concrete subclasses:

| Class | `action` value | Role |
|-------|---------------|------|
| `RuleVuln3` | `GenerateReportVuln3` | Vulnerability analysis; aggregation per library |
| `RulePerfUseSummary` | `GenerateReportPerfFromSummary` | Performance metrics; `.tar.zst` generation |
| `RuleCampaignUseSummary` | `GenerateReportCampaignFromSummary` | Campaign metrics; requires `parameters.dataPath` |
| `RuleNULL` | `NULL` | No-op; silently ignores matching files |

---

## `Index` (`publish/index.hxx` / `.cxx`)

Persists processed state in `.project/.index.json`.

```json
{
  "{commitID}": {
    "{timestamp}": {
      "file": "path/source.zip",
      "libs": ["lib1", "lib2"]
    }
  }
}
```

Key methods: `HaveIndexed()`, `Add()`, `Load()`, `Save()`.

`HaveIndexed()` returns `true` only when the entry is in the index **and** the output JSON file exists on disk — used by `ScanStorage()` to skip files.
