## `Config` (`config.hxx` / `config.cxx`)

Top-level configuration aggregate. Validates paths at startup.

`Validate(forceInstall)`:
- Canonicalizes all configured paths (storagePath, htmlPath).
- The `forceInstall` flag is accepted but currently has no effect.

---

## `ns_Server::MyServerApp` (`server/server.hxx` / `server/server.cxx`)

Extends `Poco::Util::ServerApplication`. Creates a `ServerSocket` (plain or SSL depending on config) and starts the `HTTPServer`. Blocks until `SIGTERM` or `SIGINT`.

---

## `RequestHandlerFactory` (`server/request_handler_factory.hxx`)

Routes by URI regex to typed handler classes generated by the `REQUESTHANDLER` macro. Captured URI groups become constructor arguments.

---

## `RequestHandler` subclasses (`server/request_handler.hxx` / `.cxx`)

| Handler | Route | Behavior |
|---------|-------|----------|
| `RequestHandlerNotify` | `POST /api/notify` | Parses multipart form (via `PartsHandler`), validates paths, calls `PublishAPI::NotifyFiles()` |
| `RequestHandlerProjectListData` | `GET /api/project/{name}/data` | Returns JSON list of `.project/` files for the named project |
| `RequestHandlerProjectListCampaigns` | `GET /api/project/{name}/campaigns` | Returns campaign data for rules with `"campaign": true` |
| `RequestHandlerProjectRegenerateCache` | `POST /api/project/{name}/regenerate_cache` | Drops index for the project/directory and reprocesses from scratch |
| `RequestHandlerProjectDeleteData` | `DELETE /api/project/{name}/data/{file}` | Removes a result file from the index and from disk |
| `RequestHandlerFiles` | `GET /files/{path}` | Serves from `storagePath`; if path is a project root with a `.rules` `index` field, serves from `htmlPath/publisher/` instead |
| `RequestHandlerFiles` | `GET /html/{path}` | Serves from `htmlPath`, path traversal blocked |
| `RequestHandlerCORSOptions` | `OPTIONS *` | CORS preflight response |

All handlers call `ManageCORS()` to add `Access-Control-Allow-Origin: *` headers.

## `ns_Server::PartsHandler` (`server/parts_handler.hxx` / `.cxx`)

Extends `Poco::Net::PartHandler` for multipart/form-data parsing. Reads each part's `Content-Disposition` header (`name`, `filename`, `Content-Type`) and streams the body into a `std::vector<uint8_t>`. Results stored in an `unordered_multimap<string, PartData>`.

Used exclusively by `RequestHandlerNotify` to parse the `src` and `dst` fields from `POST /api/notify`.

---

## `PublishAPI` (`api/publisher_api.hxx`)

Facade exposed to request handlers. Key methods:
- `NotifyFiles(srcs, dst, error)` — validates paths, delegates to `Publish::NotifyFiles()`.
- `ProjectListData(name, list)` — returns output file paths for a project.
- `ProjectListCampaigns(name)` — returns campaign data for a project.
- `RegenerateDataCache(name, directory)` — drops index and reprocesses.
- `DeleteData(name, file)` — removes a result file from index and disk.
- `Storage()` — returns the `storagePath`.
- `HTMLStorage()` — returns the `htmlPath`.
- `RulesIndex(path)` — returns the `index` HTML path for a given project/subdirectory path.

## `APIS` (`api/api.hxx`)

Aggregate struct holding `PublishAPI publishAPI_`. Passed by reference to the entire server layer.

## `Publish` (`publish/publish.hxx` / `.cxx`)

Background processing thread. Holds the project list and the processing queue.

- `NotifyFiles(srcs, dst, error)` — validates paths, pushes a notification to the queue and signals the worker.
- `RegenerateDataCache(name, directory)` — calls `Project::ScanStorage(regenCache=true)` under exclusive lock.
- `DeleteData(name, file)` — calls `Project::DeleteData()` under exclusive lock.
- Thread loop: wakes on notification or `orphanScanInterval`; calls `Project::ScanFiles()` for notified files or `Project::ScanStorage(false)` for the periodic scan.

Concurrency:
- Queue protected by `std::mutex` + `std::condition_variable`.
- Project list protected by `std::shared_mutex` (shared reads for notifications/queries, exclusive writes for regenerate/delete).

---

## `Project` (`publish/project.hxx` / `.cxx`)

Represents one data directory under `storagePath`. Holds:
- A list of `Rule` objects loaded from `.rules` files (recursive scan).
- A persistent `Index`.
- A map of `indexes` (subdirectory path → HTML index file) read from `.rules` files.

Key methods:
- `ScanFiles(files)` — processes a specific list of notified files; applies **all** matching rules per file; bypasses `filesInError_` and the index.
- `ScanStorage(regenCache, directory)` — periodic or forced full scan; applies the **first** matching rule per file; skips files in `filesInError_` or already indexed with a valid output JSON (unless `regenCache=true`).

`filesInError_` is in-memory only and not persisted across restarts: files that failed during a session are retried automatically on the next startup scan.
- `ListData()` — returns the list of output files tracked in the index.
- `ListCampaigns()` — returns campaign data by scanning `.zst` files under campaign rule data paths.
- `DeleteData(file)` — removes a result file from the index and deletes it from disk, along with associated source artefacts.

`.rules` files are scanned recursively from the project directory. The first `.rules` found at a level stops recursion into that subtree.

## `Rule` (`publish/rule.hxx` / `.cxx`)

Base class. Associates a regex pattern (`onFiles`) with a processing action.

Key methods:
- `Match(file)` — tests whether the rule applies: checks path prefix (literal path prefix extracted from the regex), then full regex match.
- `Apply()` — processes the archive, generates JSON, updates the index.
- `IsCampaign()` — returns true if this rule has `"campaign": true`.
- `DataPath()` — returns the literal path prefix of `onFiles`, used for campaign directory scanning.

Static factory:
- `Rule::Build(action, name, rulesPath, rulesRelativePath, filesFilter, parameters)` — returns a `RuleMergeJSON` for `"GenerateMergeJSON"`, or a `RuleNULL` for any other action.

Dead code (defined but not called by any active rule — likely left over from previous rule implementations):
- `ExtractExperimentsFromFile/Buffer()` — parses task JSON metadata from an archive.
- `MergeResults()` — merges two result documents (legacy `libs`-based JSON format).
- `UpdateJSON()` / `ValidateUpdatedJSON()` — atomic write via `.tmp` + `rename()`.

Concrete subclasses:

| Class | `action` value | Role |
|-------|---------------|------|
| `RuleMergeJSON` | `GenerateMergeJSON` | Generic configurable JSON merge rule |
| `RuleNULL` | any other value | No-op; silently ignores matching files |

## `RuleMergeJSON` (`publish/rule_mergeJSON.hxx` / `.cxx`)

Extracts a JSON file from an archive and merges it into a persistent output file.

Constructor validates all required parameters: `src`, `dst`, `merge`, `strategy` (with `comparator` and `field`).

`Apply()` workflow:
1. Extracts the task ID (timestamp) from the archive filename.
2. Resolves template variables in `src` and `dst` from the archive path. Unknown `${VAR}` tokens are left unchanged.
3. Extracts and parses `src` JSON from the archive.
4. Reads the `strategy.field` value from `src` JSON as a **uint64**.
5. Validates `keep` fields: must be present in `src`; if `dst` already exists, must also match the value stored there.
6. For each `merge` key: selects fields from `src` where the strategy comparator holds against the stored `merge_field` (also uint64) in the existing index.
7. Writes the merged document to `dst.tmp`, optionally runs `Generate_Perf_ZST` to produce a `.tar.zst` alongside the source archive, then renames atomically.
8. Returns as `libsManaged` the set of entries updated under the **first** key of `merge` (`firstMerge_`). This set is passed to `Index::Add()` and determines which archives `HaveIndexed()` considers as already processed. Keys beyond the first in `merge` are merged into the JSON but not tracked in the index.

Output file structure (`dst`):
```json
{
  "data": {
    "<keep_field>": ...,
    "<merge_key>": {
      "<field_name>": ...
    }
  },
  "index": {
    "files": [
      { "file": "path/source.zip", "task_id": "1234567890", "merge_field": 42 }
    ],
    "references": {
      "<merge_key>": { "<field_name>": 0 }
    }
  }
}
```

Template variables available in `src` and `dst` strings:

| Variable | Value |
|----------|-------|
| `${FILE_RELATIVE_PATH_N}` | N-th path segment of the archive path relative to the rule directory |
| `${FILENAME}` | Archive filename stem (no extension) |

## `Index` (`publish/index.hxx` / `.cxx`)

Persists processed state in `.project/.index.json`.

```json
{
  "{outputFile}": {
    "{timestamp}": {
      "file": "path/source.zip",
      "libs": ["lib1", "lib2"]
    }
  }
}
```

Key methods:
- `HaveIndexed(srcFile)` — returns `true` if the source file is in the index **and** the output JSON exists on disk.
- `Add(key, timestamp, srcFile, libsManaged)` — adds or updates an entry; removes `libsManaged` from older timestamps so the latest run wins.
- `Remove(rootDataPath, key, deleteSourceFiles)` — removes an entry; if `deleteSourceFiles=true`, deletes the output JSON and source artefacts with matching stem prefix.
- `Delete(dataDirectory)` — removes all index entries whose output file is under `dataDirectory`; deletes the output JSON files.
- `List()` — returns the list of tracked output file keys.
